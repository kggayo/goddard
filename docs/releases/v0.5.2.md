# Claude follow-up prompts return after checkpoint updates

Fixes a case where Claude had finished and asked a question, but Goddard never showed the `You` prompt. The terminal accepted typed text without forwarding it to the agent.

Claude can answer several checkpoint requests in one turn. Goddard now sends message IDs and matches a result to all the requests it answered, rather than expecting one result per request. Duplicate and unrelated background results cannot complete a newer user turn. Use a current Claude Code CLI for merged-message attribution; older CLIs without attribution retain the one-result-per-message fallback.

Goddard also prints a notice when you enter text outside an active input prompt. That text is not queued or reused as an answer to a later approval request. At the `You` prompt, enter your follow-up; Enter or `/done` saves and exits. At an approval prompt, `y` only approves the displayed request.

## Install or update

Node.js 24+ required:

```sh
npm install --global https://github.com/kggayo/goddard/releases/download/v0.5.2/goddard.tgz
goddard --version
```

To recover a stuck older run, press Ctrl+C once and wait for Goddard to save the handoff. Then, in the same project:

```sh
goddard note TASK_ID "Yes, create a PR."
goddard run TASK_ID --agent claude --interactive
```

Add your model and effort flags again when resuming. The saved note reaches the new session through the handoff.

Regression coverage includes a supervised fixture that merges a task and checkpoint into one result, reaches the reply prompt, and receives the user's follow-up. Adapter tests cover queued turns, duplicate/background results, legacy responses, errors, and failed sends. These tests use simulated provider responses and do not spend model quota.
