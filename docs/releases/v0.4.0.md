# Explicit permission bypass for Claude and Codex

Goddard now supports an opt-in permission bypass while keeping managed checkpoints, workspace capture, and automatic account failover. This addresses [issue #5](https://github.com/kggayo/goddard/issues/5).

## Install or update

Stop active Goddard runs, then install the release (Node.js 24+ required):

```sh
npm install --global https://github.com/kggayo/goddard/releases/download/v0.4.0/goddard.tgz
goddard --version
```

## Run with bypass

```sh
goddard run TASK_ID --agent claude --model claude-opus-5-5 --effort medium --dangerously-skip-permissions
goddard run TASK_ID --agent codex --effort high --dangerously-skip-permissions
```

- Claude uses its `bypassPermissions` mode. `--claude-permission-mode bypassPermissions` is also accepted.
- Codex uses `approvalPolicy: never` with `sandbox: danger-full-access`. This grants commands access outside the workspace and removes Codex's filesystem/network sandbox.
- The choice is shown at startup, recorded in run evidence, and preserved through automatic account switches during that invocation. It must be explicitly selected again for a new invocation.
- Existing default permissions remain unchanged. Conflicting read-only/bypass or Claude mode combinations are rejected. A Claude-specific permission mode now requires `--agent claude` instead of being silently ignored for Codex.
- User questions and unexpected provider approval requests continue to use Goddard's existing interaction handling. Provider and organization restrictions still apply.

Validation uses fixture providers to cover default and bypass settings, conflict rejection, questions, and account failover. The package also passes the cross-platform CI and isolated installation checks; these checks do not consume live provider quota. Codex's sandbox enum was additionally checked against the installed CLI's generated App Server schema.

The SQLite warning on `--version` remains tracked separately in [issue #4](https://github.com/kggayo/goddard/issues/4).
