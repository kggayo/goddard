# Create a task and get going

`goddard start` creates a task and runs your chosen agent in one command. No copying a task ID between `new` and `run`.

## Install or update

Node.js 24+ required:

```sh
npm install --global https://github.com/kggayo/goddard/releases/download/v0.5.0/goddard.tgz
```

## Start working

In your project, run `goddard init` once, then choose an agent:

```sh
goddard start "Fix the login bug and run the relevant tests" --agent codex --effort high
# Or:
goddard start "Fix the login bug and run the relevant tests" --agent claude --model sonnet --effort medium
```

- Supports all `run` options, including `--dangerously-skip-permissions`, and `--goal-file` for longer goals.
- Saves the task and handoff before launching; prints the ID and a resume command. Failed launches leave the task available for retry.
- Use `goddard run TASK_ID` to resume and `goddard list` to find saved IDs. Each `start` creates a new task. Supply your preferred run options again when resuming.
- `new` remains available for creating tasks without starting an agent. `init` remains a one-time workspace setup step.
- Invalid run options and unfinished workspace runs are rejected before creating a task.

Tests cover both providers' option forwarding, saved handoff state, goal files, invalid input, workspace ownership, launch failures, resume behavior, and exit codes without live model calls. Existing provider, account failover, and package tests also run in CI.
